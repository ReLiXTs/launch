# Что исправлено и добавлено

## 🐞 Исправленные баги

1. **Неверный путь к `server-data` (критично)**
   `src/minecraft.js` и `src/updater.js` считали путь как `launcher/server-data`,
   хотя папка находится на уровень выше — рядом с `launcher/`, а не внутри неё.
   В dev-режиме иногда «случайно» не падало явной ошибкой, а в собранном
   `.exe`/`.msi` синхронизация модов/ресурспаков/версий вообще не работала.
   → Теперь путь считается верно и отдельно для dev-режима и для собранного
   приложения (через `app.isPackaged` + `process.resourcesPath`).

2. **Запись `version.json` и временного `.zip` внутрь `app.asar` (критично)**
   После сборки код лежит в `app.asar`, который доступен только для чтения.
   Обновления скачивались, но не могли сохранить новую версию/временный архив —
   в собранном лаунчере автообновление было полностью нерабочим.
   → `version.json` теперь хранится в `app.getPath('userData')`,
   временный архив — в `os.tmpdir()`. Это соответствует тому, что уже пытался
   чинить ваш `fix-asar-path.ps1` — теперь патчить руками не нужно, скрипт
   можно удалить.

3. **Поиск Java по путям с `*` не работал**
   `fs.existsSync('...jdk-17*\\bin\\java.exe')` никогда не находил файл — маски
   `*` не поддерживаются этой функцией. Тем самым ветка кода была мертва.
   → Сначала лаунчер спрашивает `where java` / `which java`, затем реально
   сканирует папку Eclipse Adoptium через `fs.readdirSync`.

4. **Таймер проверки обновлений не останавливался**
   `setInterval` не хранился и не очищался, при закрытии приложения мог
   продолжать дёргать `mainWindow`, когда окно уже `null`.
   → Таймер создаётся вместе с окном и чистится в `window-all-closed`.

5. **Запуск без проверки, что jar-файл клиента существует**
   Ошибка была malformed («Minecraft завершился с кодом …» или тихий ENOENT).
   → Явная проверка перед запуском с понятным сообщением.

6. **Неиспользуемая зависимость `semver`**
   Импортировалась в `updater.js`, но нигде не применялась — мёртвый код и
   лишний вес пакета. Удалена.

7. **Иконка Windows-сборки**
   `package.json` указывал `.png` для `win.icon` — для NSIS/MSI это не всегда
   надёжно конвертируется. Сгенерирован `assets/icon.ico` и обновлена ссылка.

## 🔑 Вход через Microsoft (Xbox Live → Minecraft Services)

Добавлен `src/auth.js` — реализует официальный, задокументированный поток входа,
которым пользуются open-source лаунчеры (HMCL, PolyMC и т.д.):
Microsoft OAuth (PKCE, без пароля в приложении, через системный браузер) →
Xbox Live → XSTS → Minecraft Services → профиль игрока.

**Важно:** чтобы кнопка «Войти через Microsoft» заработала, нужно один раз
зарегистрировать своё приложение в Azure:

1. Зайдите на https://portal.azure.com → **App registrations** → **New registration**.
2. Имя — любое, например `Kamyshechnyy Launcher`.
3. **Supported account types** → выберите **«Personal Microsoft accounts only»**
   (это обязательно, иначе Xbox Live не примет токен).
4. Redirect URI можно не указывать сейчас (лаунчер сам поднимает временный
   `http://127.0.0.1:<случайный порт>/callback` при каждом входе) —
   но добавьте платформу **Mobile and desktop applications** и впишите
   `http://localhost` как заглушку, если Azure потребует хотя бы один URI.
5. После создания скопируйте **Application (client) ID**.
6. Вставьте его в `src/config.json` → `msal.clientId`.
7. В **API permissions** добавьте `XboxLive.signin` (обычно подключается
   автоматически при первом запросе, но лучше добавить заранее).

Без этого шага кнопка входа покажет понятную ошибку с указанием, что нужно
настроить `clientId`, а офлайн-режим (по нику) продолжит работать как раньше.

При успешном входе:
- аватар и ник берутся из настоящего профиля Minecraft;
- поле «Никнейм» блокируется (используется аккаунт);
- при запуске игры передаются настоящие `--uuid` и `--accessToken`
  (`--userType msa`), что нужно для «онлайн»-режима;
- токен `refresh_token` хранится в `userData` и шифруется через
  `safeStorage`, если это поддерживает ОС.

## Не затронуто (за рамками этой задачи)

Логика самого запуска джарника Minecraft (`buildLaunchArgs`) собирает
аргументы в упрощённом виде и не строит полноценный classpath из библиотек
Fabric/Forge — это работает только если в `server-data/versions` лежит
готовый «толстый» jar-файл, включающий все зависимости. Для полноценного
лаунчера с автоматической загрузкой библиотек потребуется отдельная,
более крупная доработка (использование `minecraft-launcher-core` или
аналогичной библиотеки) — дайте знать, если нужно это сделать отдельным шагом.
